# 06 面试问答

## 阶段 0：立项与调研

**Q1：这个项目为什么要做？之前怎么排查？**
- 产线测试失败后，链路是测试工程师 → 设备部门 FAE → 研发，跨团队流转，提单到确认根因中位数 2–3 天。
- 历史工单里有大量"现象-根因-措施"，但只能关键词搜，依赖老员工经验。
- 2025 年 2 月公司内部在昇腾上部署 DeepSeek，推动 AI 落地，借势立项。

**Q2：为什么用 DeepSeek，不用 GPT 之类？**
- 工单含产品设计和客户信息，安全要求内网私有化，不能调外部 API。
- 2025.2 华为在昇腾上已部署 DeepSeek V3/R1，平台算力组统一提供推理服务，开源可私有化、中文能力强。

**Q3：POC 怎么做的，结论是什么？**
- 三组对比（300 条抽样）：裸 LLM ≈25%，BM25+LLM ≈52%，向量+LLM ≈50%。
- 关键发现：BM25 与向量命中样本重叠仅约 60%，互补 → 双路召回；R1 太慢；FAISS 不能上生产；工单数据质量差。

**Q4：评测集怎么构建的？怎么保证可信？**
- 1,000 条已闭环、研发确认根因的工单；按产品线分层抽样，每线 ≥100。
- 按时间切分：知识库用 2024.6 前工单，评测集用 2024H2 工单，并做近重复剔除。POC 早期没做切分，命中率虚高 15 个点以上。
- 根因映射到约 2,000 个标准根因类，按类判定命中；用户与 FAE 专家交叉标注，TL 仲裁。

**Q5：为什么是 1,000 条？**
- 命中率 70% 时 95% 置信区间约 ±2.8%，能区分 5 个点以上的提升；同时是 3 人团队人工复核的上限。（`code/eval/metrics.py::wilson_interval`）

**Q6：准确率 70%→85% 是什么口径？排查时间数天→2 小时怎么算的？**
- 准确率 = 黄金集 Top3 命中率（真实根因类出现在 Top3 中）。
- 排查时间 = 系统 Top3 命中的工单，从发起诊断到工程师在工单确认根因的中位时长；基线是历史同类工单提单到确认根因的中位时长。未命中的仍走原流程，不能说成"所有故障 2 小时解决"。

**Q7：为什么要分层指标？**
- 端到端掉点时要定位：没召回（Recall@K）、召回了排得靠后（NDCG/MRR）、排在前面但 LLM 没用上（Top3 命中率 vs Recall@10 的差）。
