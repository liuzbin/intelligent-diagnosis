## #3 feat(eval): 评测脚手架

**为什么先写评测**：没有统一的尺子，后续"换向量库 / 加重排 / 微调"都无法证明有效。

| 文件 | 内容 | 阅读重点 |
|---|---|---|
| `code/eval/schema.py` | 黄金集样本、诊断请求、检索候选、诊断结果的数据结构 | 为什么用"标准根因类 ID"判定命中、为什么 gold 是列表 |
| `code/eval/metrics.py` | Recall@K、MRR、NDCG、Top3 命中率、ECE 校准误差、Wilson 置信区间 | 分层指标如何定位问题；1000 条样本 ±2.8% 的由来 |
| `code/eval/splitter.py` | 时间切分、产品线分层抽样、与知识库近重复剔除 | 防泄漏三板斧 |
| `code/eval/runner.py` | 以 Protocol 抽象诊断链路，信号量控制并发跑评测，聚合分层报告 | Protocol 让任意链路版本可公平对比；并发度为什么要限制 |
